# 电致变色测试数据整理规范

## 目的

规范光谱电化学、响应时间、循环稳定性、CV/CA、CIE 等测试数据在实验记录本中的记录方式，使记录同时满足日常查看和后续自动提取整理。

## 总体原则

每一批测试数据采用“实验记录 + 结构化数据文件 + 总索引”的形式保存。

- 实验记录负责记录背景、测试条件、结果表、异常说明和分析结论。
- 结构化 JSON 负责保存可机器读取的样品级数据。
- 总索引记录每批测试数据的位置、类型和关键结论，便于跨批次检索。

## 命名规则

### 实验记录

有测试数据的实验记录，标题必须包含具体数据类型标签，而不是统一写成泛化的“含测试数据”。常用标签如下：

```text
[含光谱电化学数据]
[含膜厚数据]
[含循环稳定性数据]
[含电化学数据]
```

frontmatter 标签必须包含 `数据已整理` 和相同的数据类型标签：

```text
含光谱电化学数据, 数据已整理
含膜厚数据, 数据已整理
```

示例：

```yaml
title: "[含光谱电化学数据] 单双层ATO液态器件测试与旋涂样品编号记录"
tags: [含光谱电化学数据, 数据已整理, ATO, 液态电解质, 光谱电化学, 响应时间]
```

### 结构化数据文件

结构化数据保存到 `data/` 目录，文件名建议：

```text
YYYY-MM-DD-{主题}-{测试类型}.json
```

示例：

```text
data/2026-07-04-ato-liquid-spectroechem-response-time.json
```

### 总索引

所有批次统一登记在：

```text
data/electrochromic-test-index.json
```

## 实验记录正文结构

有测试数据的记录正文中，应固定包含以下部分：

1. 测试体系与数据来源
2. 关键结论或重点结果
3. 结果汇总表
4. 数据质量说明
5. 结果分析
6. 初步结论与下一步

结构化 JSON 的字段说明放在本方法文档中维护；单条实验记录正文不再重复展示字段表，以免占用阅读空间。
原始数据、处理结果、结构化 JSON 和总索引的位置应记录在结构化 JSON 或 `data/electrochromic-test-index.json` 中，正文不单独展示“数据入口/保存位置/用途”表。

## 样品级 JSON 字段

每个样品建议至少包含以下字段：

| 字段 | 含义 |
|------|------|
| `sample_id` | 稳定样品编号，如 S01 |
| `sample_name` | 原始测试文件/样品名 |
| `date` | 测试日期 |
| `system` | 器件体系 |
| `ato_layers` | ATO 层数或其他关键变量 |
| `voltage_window` | 电压窗口 |
| `pulse_time_s` | 脉冲时间 |
| `lambda_max_nm` | 最大对比度对应波长 |
| `max_contrast_percent` | 最大光学对比度 |
| `recommended_cycle` | 推荐取值循环 |
| `tc_s` | 着色响应时间 |
| `tb_s` | 褪色响应时间 |
| `data_status` | `valid`、`needs_review` 或 `excluded` |
| `quality_note` | 数据异常、排除原因或重点说明 |

## 数据质量规则

- 光谱文件夹、同名电化学文件、处理结果必须按样品名匹配。
- 光谱 txt 文件名前缀必须与样品名一致。
- 若发现混入其他样品、前缀不一致、循环异常或拟合失败，应标记为 `needs_review` 或 `excluded`，不能强行纳入主要结论。
- 实验记录中的主要结论只基于 `valid` 数据，异常数据必须在“数据质量说明”中单独列出。

## 后续自动汇总方式

后续需要跨批次分析时，优先读取：

```text
data/electrochromic-test-index.json
```

再按索引中的 `data_file` 读取每批 JSON。自然语言实验记录只用于解释和追溯，不作为主要数据源反向解析。
